# AuthServer – Media Collection - User's Avatar

**Developer:** Daniel Ambrózio de Oliveira  

This repository continues [AuthServer – Media Collection](https://github.com/dambrozio/authserver-media-collection), which contains the original authentication and media collection project. This continuation documents the AWS integration and user avatar features.

## User avatars

When an avatar is generated, the server:

1. Looks up the user's avatar via [Gravatar API](https://docs.gravatar.com/sdk/images/).
2. If Gravatar has no image, requests a PNG of the user's initials from [UI Avatars](https://ui-avatars.com/).
3. Downloads the image and stores a copy in the AWS S3 bucket.

The user record stores the application's avatar path; the full URL is generated by the storage service.

### Avatar endpoints (user-controller)

| Method | Endpoint | Description |
| --- | --- | --- |
| `GET` | `/users/{id}/avatar` | Get a user's avatar URL |
| `GET` | `/users/me/avatar` | Get the authenticated user's avatar URL |
| `PUT` | `/users/{id}/avatar` | Upload an avatar (owner or admin) |
| `DELETE` | `/users/{id}/avatar` | Regenerate the avatar (owner or admin) |

Note:

`DELETE` regenerates the avatar rather than leaving the user without one. 

`ADMIN` can manage another user's avatar; other users can only change their own. Avatar GET endpoints are public in the current security configuration.

## AWS S3

The Elastic Beanstalk EC2 instance profile needs `s3:GetObject` and `s3:PutObject` permissions for authserver's avatars bucket path. 
The bucket must allow reads for avatar URLs to load directly in a browser.

The current `S3Storage` code uses `EnvironmentVariableCredentialsProvider`, which reads `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`.
